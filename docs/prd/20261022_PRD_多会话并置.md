# PRD 多会话并置

创建日期：2026-10-22

## 一句话需求

在不切换标签的前提下，把多个进行中的会话并排放在一个窗口里持续可见，
一眼看到它们各自的进度，并能对其中任意一个直接下手。

## 名词表

术语第一次出现时配一句人话解释，下文不再重复。

| 术语 | 人话解释 |
|---|---|
| 会话（Session） | 一条具体的对话 |
| 工作区（Workspace） | 一个项目目录，下面挂着一批会话 |
| 格子（Cell） | 分屏后的一块矩形区域，里面装一个会话 |
| 窗口（SplitWindow） | 一个可独立分屏的顶层窗口，一个显示器对应一个 |
| 持有（retain） | 向 DSH 声明「这个会话我还要用」，DSH 因此保证它不被卸载、继续在后台运行 |
| 可订阅快照（ObservableSnapshot） | 一份会主动通知变化的会话状态数据，订阅后状态一变就能收到通知 |

## 要解决的痛点

同时跑着几个任务时，它们在后台跑的状态是看不见的。不知道哪个跑完了、
哪个卡在等待审批、哪个已经失败。只能挨个点进去看，再退出来，再点下一个。
要消灭的是这个「挨个点」的动作。

分屏是手段，并行监督才是目的。

## 两条主干原则

### 原则一：点哪打哪

每个格子都是一个完整会话，点过去就能直接输入。不存在只读模式，
也不存在「先进入编辑模式」这个额外步骤。

### 原则二：分屏状态不变

点击只改变「当前会话是哪个」，不改变布局。进入分屏后布局就定住了，
不因点击、不因切换会话、不因某个会话跑完而变化。唯一能改变布局的，
是用户显式地拖分割条、换预设、或点按钮退出。

这条原则排除了一类常见设计：点击某格后该格自动放大。放大是用户显式操作
（格子头部的最大化按钮），属于主动行为，点击的副作用里没有它。

「不变」覆盖的范围：

- 不重新排列格子、不重新分配尺寸、不自动最大化任何格子
- 有会话结束或新建时，不自动收起或重排
- 切换工作区、重启 DSH，布局保持原样
- 唯一允许的视觉变化是当前格的边框高亮，它不改变几何尺寸，
  用来提示键盘输入会进到哪一格

## 范围说明：「一分为四」是例子

原始描述里「可以一分为四」与「如果有多屏就可以放更多」并存，因此四个
只是一个举例数字。真正的规格是 N 宫格，二、三、四、六、九都支持，
由屏幕尺寸与用户决定，布局可自由重排。

本项目做的是多会话布局编排器。它的输出是一套通用壳，四分屏是这套壳的
一个预设。

## 交互设计

### 进入与退出

- 点击窗口框架左上角的按钮进入分屏模式，再点一次回到单会话模式
- 快捷键建议用 `Ctrl/Cmd + \`
- 退出时销毁视图，保留会话。所有格子里的会话都处于持有状态，
  退出分屏只是收起视图，会话继续在后台运行
- 布局被记住，下次进入恢复上次的排布

### 装填格子

三种方式，按使用频率排序：

1. 拖：从左侧会话列表把会话直接拖进格子
2. 选：空格子显示「最近活跃会话」下拉，按最近活跃时间排序
3. 自动：一键填充当前正在运行的会话，自动铺满空格子

### 点击的行为

- 点任意格子的任意位置，该格成为当前格，仅此而已，格子不动不重排
- 每个格子自始至终带自己的输入框，随时可输入
- 非当前格的输入框折叠为一行，点击就地展开为完整输入框。
  展开只覆盖格子底部，不撑大格子、不重排。折叠状态下它依然完整可输入
- 当前格的唯一视觉标识是边框高亮
- 当前格的会话即 DSH 全局当前会话，主面板语义不变

### 每个格子的常驻信息

无论哪个格子，格子头部都常驻：

- 会话标题与所属工作区
- 状态灯：运行中、等待审批、已完成、出错、空闲
- 未读角标：后台格子有新输出但未查看时点亮
- 最大化此格、移出此格、换一个会话

状态灯的刷新方式可配置，见决策表 Q5。

### 布局

- 预设：二栏、三栏、四宫格、六宫格、主加副（一个格子占大半屏，其余堆叠）
- 格子间可拖拽调整比例
- 格子间可拖拽交换会话
- 一个格子可弹出为独立窗口
- 窗口之间可互相拖会话

## 决策记录

九项分歧点已全部拍板，实现以本节为准。

| 编号 | 问题 | 结论 |
|---|---|---|
| Q1 | 格子显示完整对话流还是摘要卡片 | 完整对话流，复用 DSH 原生渲染器 |
| Q1b | 多显示器怎么处理 | 多显示器即多窗口，每窗口独立 m×n，两边格子数可不同 |
| Q1c | 格子数上限 | 两层，全部可配置，见下节 |
| Q2 | 几个格子能打字 | 每个格子都能打字 |
| Q2b | 非当前格的输入框 | 折叠为一行，点击就地展开 |
| Q3 | 格子的单位是会话还是工作区 | 两者都要，可切粒度 |
| Q3b | 工作区粒度的格子里显示什么 | 永远只显示一条会话 |
| Q4 | 布局归属 | 分屏跟窗口，不跟项目 |
| Q5 | 状态灯实时性 | 用户可配置，默认轮询 |

### Q1c 两层上限

| 层级 | 软限制 | 硬顶 | 能否调 |
|---|---|---|---|
| 单窗口 | 6，随配置浮动，接近时提示但允许继续 | 12 | 可 |
| 全局总量，即所有窗口的格子之和 | 无 | 20 | 可 |

两条同时生效：单个窗口最多 12 格，所有窗口加起来默认不超过 20 格。
开满需要至少两个窗口，单个窗口无论全局上限调到多高都超不过 12。

四个数值全部可在设置里配置，默认值即上表。收敛规则：

- 该窗口实际可开格数取两层中更严格的那个，等于单窗口硬顶与全局剩余额度的较小值
- 单窗口硬顶被调到高于全局总量时不报错，按上式自动收敛
- 软限制被调到高于硬顶时同样收敛为硬顶
- 设置界面在两者矛盾时给行内说明，不弹错误打断用户
- 手填值优先于自动推导值，留空则回到按内存等指标自动推导

### Q3b 工作区粒度的确切含义

装着整个项目的格子，内部依然只显示一条会话，与会话粒度的格子完全一致。
两者的唯一区别是格子顶部的会话切换条：工作区粒度把候选范围限定在该项目下，
会话粒度则用全局最近活跃。

因此不存在项目概览视图，不存在聚合状态灯，输入归属问题自动消解，
输入永远发给当前显示的那条会话。

### Q4 布局归属的确切含义

每个窗口记住自己的布局，包括 m×n、各格装什么、当前格是谁。
切换工作区不影响任何分屏布局。两个窗口可有完全不同的布局，互不干扰。
不存在按项目记忆布局的机制，例如项目 A 固定四格、项目 B 固定两格。

### Q5 状态灯刷新方式

做成设置项，建议放进 DSH 设置页的常规区。

| 选项 | 实现 | 适用 |
|---|---|---|
| 节能，默认 | 定时轮询，几秒延迟 | 格子多、配置一般、或只是偶尔瞥一眼 |
| 实时 | 订阅可订阅快照，状态变化立刻亮灯 | 需要第一时间知道哪个会话在等待审批 |

两档的数据源相同，差别只在取数方式：轮询是定时读取快照，实时是订阅快照变更。
切换无需重启、不影响布局。

## 验收标准

1. 能在一个窗口里同时看到 4 个进行中的会话，且它们在不查看时也在运行
2. 某个后台会话需要审批时，那个格子的状态灯变色、角标出现，
   无需挨个点进去巡查
3. 点任意一个格子就能立即在里面继续对话，延迟与单会话模式无感差异
4. 在单会话模式与分屏模式之间进出，不丢会话、不中断运行中的任务
5. 布局在重启 DSH 后保留
6. 点任意一个格子就能立刻打字，无需先激活、无需等待、布局纹丝不动
7. 进入分屏后，除显式操作（拖分割条、换预设、退出）外布局永远不变
8. 两个窗口可有不同格子数，且窗口之间可互拖会话
9. 格子数达到上限时给出提示，且上限可在设置里调整

## 暂不包含

以下事项明确划到范围外，避免需求膨胀：

- 跨格子的消息转发与合并
- 移动端与窄屏适配，窄屏直接退化为单会话加会话切换器
- 自定义格子外观，沿用 DSH 主题
