# 分屏插件测试用例

## 环境
- DSH web profile，Windows，dsh 0.2.1-rc.2
- 插件包 `dsh-workspace-split` 已 link 安装

## 用例

### TC-01 插件加载
- 步骤：启动 `dsh web`，浏览器打开首页
- 预期：侧边栏正常渲染，无 "Failed to load plugins" 报错

### TC-02 入口可见性（hero 页面）
- 步骤：未选任何会话，停留在 hero 页面
- 预期：「⊞ Split」按钮出现在 hero 区域 options 行（「标准模式」旁）

### TC-03 切换到分屏
- 步骤：hero 页面点「⊞ Split」
- 预期：主区域从 hero 切换为分屏面板，显示当前网格的格子与会话选择器

### TC-04 切回会话
- 步骤：分屏面板下再点「⊞ Split」
- 预期：主区域恢复 hero 页面

### TC-05 入口可见性（激活会话）
- 步骤：进入一个激活会话（有对话记录）
- 预期：「⊞ Split」按钮出现在会话 header actions 行

### TC-06 激活会话切换分屏
- 步骤：激活会话页面点「⊞ Split」
- 预期：主区域切换为分屏面板；再点恢复会话内容

### TC-07 分屏面板格渲染
- 步骤：进入分屏面板
- 预期：显示 N 个格子，每格有会话选择器占位

### TC-08 刷新持久化
- 步骤：分屏状态下刷新页面，再点「⊞ 分屏」
- 预期：格子分配恢复（gridSize + 每格选中的会话）

### TC-09 格子内会话内容渲染
- 步骤：格子选中会话后，格内显示该会话的消息流
- 预期：user/message、assistant/message、思考过程、工具调用、turn 分隔线等内容
  按序渲染，自动滚动到底部

### TC-09a 运行过程可见
- 步骤：发送一条会触发模型思考 / 工具调用的指令
- 预期：思考内容与工具调用折叠在「处理过程」组里；运行中该组默认展开并显示
  「处理中」，工具行在结果返回前标「运行中…」；结果返回后停止；底部状态行依次
  显示「正在思考…」「正在运行 bash…」「正在生成回复…」等，本轮结束后消失；
  已完成的轮次可点组标题收起/展开

### TC-09b 失败与中止可见
- 步骤：在模型不可用 / 网络断开时发送；再在运行中点击发送键（此时已变成停止键）
- 预期：失败显示红色「运行失败：<message>（<code>）」行；点停止后显示「本轮已中止」，
  状态行消失，草稿保留

### TC-09c 队列可见与操作
- 步骤：运行中再发送一条消息（会进入队列）
- 预期：输入框上方出现「队列（1）」与消息文本，提供「插话」和「移除」；
  点「移除」后队列消失且该消息不再发送；点「插话」后消息进入当前运行的下一步

### TC-10 格子内直接输入
- 步骤：格子底部输入框输入文字，回车或点「发送」
- 预期：消息通过 session.prompt() 进入会话，输入框清空，焦点保持

### TC-10a 格子内输入图片（选择）
- 步骤：点输入框左侧的图片按钮，选择一张 PNG/JPEG/WebP/GIF
- 预期：输入框上方出现 46px 缩略图，可点右上角 × 移除；发送后缩略图清空，
  会话记录里的用户消息显示同一张图片

### TC-10b 格子内输入图片（粘贴 / 拖放）
- 步骤：从截图工具复制图片后粘贴到格子输入框；再把图片文件拖到输入框卡片上
- 预期：两种方式都加入缩略图条；拖放经过时卡片出现内嵌高亮环；
  拖入不支持的类型（如 SVG）时显示本地错误而不是静默忽略

### TC-10c 纯图片与图文混合发送
- 步骤：只放一张图（不输入文字）点发送；再输入文字并附两张图发送
- 预期：纯图片也能发出；图文消息按“图片在前、文字在后”的 prompt parts 顺序
  发送（与 DSH 主输入框一致）；会话记录中图片显示在文字上方

### TC-10d 发送失败可见
- 步骤：在 Host 会拒绝的条件下发送（例如图片超过 Host 限制）
- 预期：输入框上方显示 Host 返回的 code + message，草稿与图片不丢

### TC-11 状态灯
- 步骤：格子 header 左侧圆点显示会话运行状态
- 预期：运行中绿色，空闲灰色

### TC-12 分屏状态自动恢复
- 步骤：分屏激活状态下刷新页面
- 预期：页面加载后自动回到分屏，格子分配完整

### TC-13 网格选择器（仿插入表格的悬停交互）
- 步骤：点工具栏的「网格」按钮，在 10×10 方格上悬停
- 预期：弹出的面板标题实时显示「N 行 × M 列 · 共 K 格」，已选方格高亮；
  点击后面板关闭并切换布局；键盘方向键可移动选择，回车生效

### TC-13a 软限制（6 格）
- 步骤：悬停选中 2×4（8 格）并点击
- 预期：弹出确认框「打开 8 个格子？」并提示可能卡顿；取消不改变布局，
  「仍然继续」后布局变为 2 行 4 列

### TC-13b 硬顶（10 格）与解锁提示
- 步骤：悬停选中 3×4（12 格）并点击
- 预期：不切换布局，弹出「需要解锁 12 格」提示，说明去 设置 → 通用 →
  分屏网格 调整；面板下方同时提示「超过上限 10 格，去设置解锁」

### TC-14 上限可配置
- 步骤：设置 → 通用 → 分屏网格，把「最多格子数」改为 12，
  「超过此数须确认」改为 4
- 预期：无需重启，3×4（12 格）可经确认框生效；5 格起就弹确认框；
  分屏面板和选择器立即跟随新上限

### TC-16 旧布局迁移与缩容保留
- 步骤：localStorage 里保留旧版 `{ gridSize: 5 }` 后刷新；再切到 2×2，然后切回 3×3
- 预期：旧布局按新硬顶收敛为最接近方形的 3×3（9 格），布局不报错；
  缩到 2×2 时被隐藏的格子分配不丢失，切回 3×3 后恢复

### TC-17 键盘与窄窗口
- 步骤：键盘打开选择器，选中 2×4 触发确认框；Tab 到「仍然继续」后等待会话更新；
  再把窗口高度压到 400px 以下
- 预期：焦点不会被会话更新抢回「取消」；取消/Esc 后焦点回到网格；
  选择面板不被主区域裁切，可滚动看到 7–10 格

### TC-15 Windows 桌面端（web profile）验证
- 步骤：Windows 上 `dsh web` 安装同一插件，打开页面操作
- 预期：与 WSL 行为一致，大目录（600+ 会话）下正常

### TC-18 图片与文件附件
- 步骤：在格子输入框依次粘贴图片、拖入文件、用 `+` 菜单分别选择图片和文件；
  观察草稿条、上传进度与移除按钮；发送后看用户消息
- 预期：图片进入缩略图条，其他文件显示文件名/大小/上传状态；可单独移除；
  发送后消息里同时出现文件卡与图片，文本为空也能发；上传失败显示错误且不误发

### TC-19 模型、推理等级与访问模式
- 步骤：点输入框下方的模型座位切换模型/推理等级；点访问模式座位切到
  「工作区内修改」；再点「完全权限」观察风险确认
- 预期：座位显示当前模型与等级；切换后投影回填；访问模式使用
  `/permission <preset>`；完全权限必须先确认，取消不改变当前值

### TC-20 斜杠命令与 @ 引用
- 步骤：输入 `/definitely-not-a-command` 回车；再输入 `@` 观察候选并选择一项
- 预期：未知命令显示「未知命令」且草稿保留；合法命令不进入对话轮次；
  `@` 弹出文件/会话候选，选中后插入 `@path` / `@"path"` / 会话 mention 文本

### TC-21 审批与提问卡
- 步骤：在一个格子绑定的会话里触发需要审批的工具（或 ask_user_question），
  在分屏里观察输入框位置
- 预期：输入框被紧凑卡片取代；审批显示工具名与「拒绝 / 允许一次」，
  Esc 拒绝；提问逐题显示选项与自定义输入，通道未就绪时按钮禁用；
  回答后卡片消失，官方主面板同步收起

### TC-22 上下文占用
- 步骤：给有 `contextPressure` 投影的会话绑定格子
- 预期：输入框下方显示 `百分比 · ~used / window`；投影缺一半时整块不显示，
  不出现 0%

### TC-23 DSH 契约测试
- 步骤：`node test/dsh-contract.test.js`；改坏任意一个被断言的成员名再跑
- 预期：正常安装下 5 条全过；缺失成员时失败信息直接打印文件与缺失符号；
  没装 DSH 的机器整组跳过

### TC-24 DSH 浏览器回归（headless）
- 步骤：`node --test test/e2e/dsh-composer.test.js`（需要本机 `dsh`、Chrome 和已构建的
  `client.js`；缺任一项自动跳过）
- 预期：临时 DSH home + 临时 Chrome profile 启动后，`?dsws-test`/localStorage 开关
  通过受控 fixture 渲染审批卡、提问卡、过程组耗时、上下文 footer、@ 候选、
  模型菜单、权限风险确认、文件草稿条和项目标题；全部通过，临时目录与进程清理干净

### TC-25 标题项目徽标与对齐
- 步骤：在两个格子里分别绑定不同项目的会话，观察标题头；把其中一格用 Ctrl+滚轮
  放大/缩小，再缩窄窗口并让项目名很长
- 预期：标题前显示项目名徽标，不同项目颜色不同；**项目徽标字号与会话标题一致**，
  徽标、状态点、标题、重命名和选择器在同一行垂直居中；标题头按格子宽度自动缩放
  （不会比正文过大），但手动 Ctrl+滚轮只改正文、不改标题头，因此**两格手动缩放
  不同时标题头仍对齐**；项目名过长时先截断徽标，会话标题仍可读；无项目时回退到
  cwd 目录名，两者都没有则只显示会话标题

## 自动化回归（E2E）

`npm run test:e2e` 用本机 Chrome/Chromium 的无头模式跑 `test/e2e/`：静态服务起一个
复刻桌面端 footer 结构的页面（含 slot 的 `display: contents` 包裹层、mobile 入口
与账号行），加载插件真实的 `src/layout.js`。

- TC-E2E-01 侧栏控件垂直居中对齐账号行：断言实测偏移 ≈ 60.3px、控件中心与账号行
  中心偏差 < 0.6px。这条是桌面端「图标浮在两行之间」的回归用例——用旧写法
  （`parentElement.nextElementSibling`）会直接失败。
- TC-E2E-02 折叠态：shell 的 `data-sidebar-collapsed="true"` 必须压过内联
  `translateY`，计算样式回到 `none`。

找不到浏览器时整组跳过（可设 `DSWS_CHROME` 指定路径）。

## 已知限制
- 完整发送链路（prompt → LLM 回复）需要 API key，测试环境未覆盖
- 图片的字节/像素/模型模态限制由 Host 校验；客户端只预检类型与数量
- 多显示器场景使用浏览器多窗口（每窗口独立 localStorage）
