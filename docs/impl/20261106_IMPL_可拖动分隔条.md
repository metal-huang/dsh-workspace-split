## 本轮改了什么

| 改动 | 用户能看到的变化 | 主要文件 |
|---|---|---|
| 列可拖 | 两列之间出现一条细线，拖动改变列宽；双击回到等分 | `src/split-ratios.js`、`src/client.js` |
| 行可拖 | 两行之间同样有一条线，拖动改变行高 | 同上 |
| 下限按文字算 | 列拖到 18 个中文字宽停住；行拖到「表头 + 4 行」停住 | `src/grid-limits.js` |
| 去掉按宽度自动缩放 | 两格字号不再随宽度变化，也不再一大一小；每格可用 Ctrl+滚轮单独放大 | `src/zoom.js`、`src/client.js` |
| 比例持久化 | 刷新后列宽行高保持 | `src/client.js`（`dsws-layout`） |

## 关键取舍（为什么这么做）

- **不做嵌套分割树，只调规整网格的行列比例。** 格子是 `rows × cols` 的网格，列宽整列共享、行高整行共享；要做“每格独立边界”等于换掉布局引擎，不在本轮范围内。
- **下限由文字推出，不写死像素。** 18 个中文字按 1em 计，行按实测行高计；字号变了下限跟着变，避免“格子窄到放不下字”。列宽下限另加 24px 的内边距，行高下限另加实测的表头高度。
- **表头高度运行时测量，不用 `minHeight`。** 样式里写的是 36px，实际渲染是 53px（标题行、项目徽章、内边距叠加）。写死会让行下限少算 17px，拖到底时只剩标题、没有正文。
- **下限只作用于拖拽，不写进 `grid-template`。** 模板仍是 `minmax(0, Xfr)`：面板比“所有下限之和”还窄时，写死下限会让网格溢出容器；夹取放在 `resizeTracks` 里，够不到下限时按当前值退让。
- **拖动时不走 React 渲染。** 指针移动直接写 `grid-template-columns/rows`，松手才 `setState`；否则每帧都会重渲染全部格子（对话流、输入框、Markdown）。
- **去掉按宽度自动缩放（行为变化）。** 原实现挂 `ResizeObserver` 读格子宽度算字号，拖动时宽度连续变、字号连续变，视觉上在抖；两列宽窄不同时两格字号也不一致。代价是窄格子不再自动缩小，改由用户 Ctrl+滚轮决定。
- **不做键盘调整。** 本轮只承诺鼠标拖拽与双击复位；`role="separator"` 与 `aria-orientation` 保留，键盘交互留到后续。

## 踩过的坑

- **行下限最初只算了 4 行文字。** 96px 的行高里表头占 53px，实际只剩两行多；加上表头后是 149px。
- **`getComputedStyle(...).lineHeight` 可能是 `normal`。** `parseFloat` 得到 `NaN`，此时按 1.5 倍字号兜底，否则下限会算成 0。
- **权重四舍五入到三位小数会让下限差几像素。** 312px 的下限实测落在 311.7px，视觉无感；下限判断留 8px 容差。
- **合成 PointerEvent 拿不到 pointer capture。** `setPointerCapture` 对合成事件会抛异常，包了 try/catch 才能用脚本驱动拖拽；真实指针不受影响。
